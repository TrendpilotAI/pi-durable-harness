## Execution requirements for the agent team (mandatory)

1. Run the team for real. Every non-orchestrator role listed above must be executed as a separate sub-agent through the `agent` tool. Simulating a role in your own turn does not count. You, the orchestrator, do not write the module or tests yourself; you set up the project, delegate, verify, and integrate.

2. One stage at a time. Launch a worker only when the inputs it needs already exist on disk.

3. Self-contained instructions. A worker sees nothing but your prompt and the filesystem. Each `task` must include: the absolute workspace path, the exact files to create or modify, the interfaces it must use, the command to run to verify, and the report you expect back.

4. Verify before you build on it. After each report, check the worker's output yourself (run the tests). If the check fails, re-delegate to the same role with a corrected, narrower instruction instead of fixing it yourself.

5. Finish cleanly. Your final answer must summarize every worker call: role, what it was asked, status, and what you verified.
